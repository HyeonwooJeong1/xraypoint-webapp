# xraypoint — 하반신 정렬 자동 측정 웹앱

브라우저에서 전장 X-ray의 좌우 15개 랜드마크와 mHKA·MPTA·LDFA·JLCA·WBL을 계산합니다. 영상은 서버에 전송하지 않습니다.

## 배포 버전과 변경 내역

화면 상단에서 실행 중인 버전과 [변경 내역](CHANGELOG.md)을 확인할 수 있습니다. 앱 버전의 정본은 [version.json](version.json)이며, 모델 자산의 release·SHA256과 구분합니다.

수정할 때마다 버전과 변경 내역을 갱신하고, 범위에 맞는 검사 후 실제 GitHub Pages에 반영합니다. 버전별 커밋·`vX.Y.Z` 태그를 보존하며 Pages 성공과 공개 화면 확인까지 끝나야 배포 완료입니다. 절차는 [AGENTS.md](AGENTS.md)에 있습니다.

배포 전 `node tools/check-release.cjs --previous <현재 공개 버전>`으로 버전 증가, 화면·캐시·변경 내역·모델 메타 일치를 검사합니다. 기존 검증 배포 b8a0c87은 이 운영 방식의 기준 버전 3.0.0으로 기록했습니다.

## 모델 목록과 다운로드

최신 라벨·학습90/검증10/내부test0 기준의 6종만 제공합니다. 성과가 없던 추가 실험, 구 라벨 및 80/10/10 모델은 목록에서 제외했습니다.

| 관절 | 기본 선택 | 추가 다운로드 | 파라미터 수 / 파일 용량 |
|---|---|---|---|
| 골반 | B0 | HRNet-W32 | B0 약6.25M / 23.4MB, HRNet 약35.99M / 144.1MB |
| 무릎 | B0 + HRNet-W32 | — | 같은 규모, 입력384×384 |
| 발목 | B0 | HRNet-W32 | 같은 규모, 입력256×256 |

공통 위치 탐지 모델은 최신 라벨·90/10으로 학습한 stage1_90입니다. 기본 모델 준비가 끝나면 영상 분석을 사용할 수 있습니다. 공개 배포 여부는 별도 배포 보고서가 기준입니다.

1. 접속 후 기본 모델 준비가 끝나면 X-ray 파일을 엽니다. 여러 장을 순차 처리합니다.
2. **모델 선택·다운로드**에서 관절마다 하나 이상 선택합니다. 추가 모델은 먼저 다운로드 버튼으로 받습니다.
3. 여러 모델을 고르면 같은 입력의 raw heatmap을 동일 가중 평균한 뒤 DARK를 한 번 적용합니다.
4. 선택 적용은 현재 영상을 분석합니다. 이전 조합을 다시 선택하면 그 결과와 수동 수정점을 복원합니다.
5. 점을 드래그하면 각도를 다시 계산합니다. CSV·PNG에는 해당 영상에 사용한 세 관절 모델이 기록됩니다.

모델 파일은 SHA256 검증 후 CacheStorage에 저장하여 같은 브라우저에서 재사용합니다. 사이트 데이터 삭제·공간 정리 시 재다운로드가 필요합니다. 환자 영상과 수정점은 현재 탭 메모리에만 남으며 새로고침하면 초기화됩니다. 기본 관절 모델 합계214.4MB, 선택 모델 전체502.6MB에 stage1 용량이 더해집니다. 필요한 모델 세션만 메모리에 유지합니다.

## 실행

공개 GitHub Pages 주소를 열거나, 이 폴더의 serve.bat를 실행하여 http://localhost:8180 에 접속합니다. index.html을 file://로 직접 열면 모델 로딩이 불가능합니다. Chrome에서 검증했으며 다른 브라우저·저메모리 기기는 별도 확인이 필요합니다.

단축키: P 점 / A 축선 / L 점 이름 / 1~5 각도 / 6·7 좌우 / 8·9·0 관절 확대창. 좌우는 환자 기준, 저장 좌표는 원본 픽셀입니다.

## 개발·검증

- app.js: 관절별 선택·추론 큐·수동 수정점 캐시·CSV42열/PNG.
- ensemble.js: 메타 검증, 히트맵 평균, 해시 검증과 모델 저장소.
- models/meta.json: 정확한 체크포인트·파라미터 수·다운로드 자산·학습 세대.
- tools/export_web_catalog.py: 최신 관절6종 변환과 PyTorch/ONNX 5입력 대조.
- tools/export_web_stage1_90.py: 완료된 stage1만 출처 검증 후 변환. 학습 중 best.pt는 거부.
- node --test tests/webapp_ensemble.test.cjs: 선택·평균·오류·해제·저장소 회귀 검사.
- node tools/check_web_catalog.cjs: Chrome/WASM 수치, 추가 다운로드, 재접속 캐시, 전체 파이프라인·수정점 보존 검사. stage1 미완료 시 해당 범위는 검사하지 않고 pending 보고서로 분리합니다.

검증 파일은 연구 저장소 docs/collaboration/에 보관합니다. 외부400 정확도 재평가와 변환/웹앱 동작 검증은 별개입니다. 이 작업으로 성능 우월성을 주장하지 않습니다.

배포 시 코드·lib·meta와 meta가 참조하는 모델 자산만 복사하세요. models/의 과거 파일이나 runs/의 영상·체크포인트·검증 입력을 일괄 복사하지 마세요. FP32 외부 가중치 조각은 각48MiB 이하이며 하나라도 누락/손상되면 추론을 중단합니다.

### 모델별 정규화 오차 비교 (v3.2.0)
모델 선택 창에서 각 점의 B0·HRNet·앙상블 테스트셋 평균 오차율을 확인합니다. 평가: 2026-11-05, 외부 200영상·400다리, GT amal, 최신 stage1 및 배포 체크포인트. 분모는 같은 다리 GT p5–p6 거리이며 낮을수록 좋습니다. PyTorch float32 평가이며 업로드 영상의 개별 오차가 아닙니다. 집계 정본은 model-errors.json입니다.
